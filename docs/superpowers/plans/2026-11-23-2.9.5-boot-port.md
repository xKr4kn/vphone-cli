# 2.9.5 boot-path port

**Goal:** carry the live-validated A/B kernel transaction onto the 2.9.5 source and validate `cfw update-kernel` → boot → `cfw boot-commit` for both slots on `vphone26s`.

**Architecture:** cherry-pick the tested 2.9.4 boot commit `4a672e5d6b` onto the 2.9.5 tag `4c009442`; resolve only source differences in the installer and command registration; keep the 2.9.5 kernel patch pipeline untouched; build, admit, install, then exercise the live two-slot commit path.

**Spec:** `Research/Firmware/boot-admission.md` (in the main checkout at `4a672e5d6b`; copy from the boot commit).

## Global Constraints

- Do not change the 2.9.5 kernel patch catalog or add a patch declaration for this port.
- Do not modify the 2.9.4 tree; the port lives on `port/2.9.5-boot` in `.worktrees/2.9.5-port`.
- The A/B transaction keeps the 4 GiB kernel-transaction floor and the 50 GiB full-install floor.
- The live target is `vphone26s`, the throwaway twin; `vphone26` is left untouched.
- No `cfw install`, no host security changes, no machine creation.

## Review Focus

- A `BootState` written by the 2.9.5 port must be readable after a sim/stop cycle and by `cfw boot-commit`.
- A candidate from the 2.9.5 pipeline that differs from the active kernel must boot before commit is allowed.
- The second-slot update must target the other slot after the first commit.
- The root rollback must remain available after a failed candidate.

## Task 1: Port the boot transaction

**Files:** the files in `4a672e5d6b`; conflicts only in
`VPhoneExecutable/VPhoneCommand/VPhoneCommand/Firmware/VPhoneCustomFirmwareInstaller.swift`
and `VPhoneExecutable/VPhoneCommand/VPhoneCommand/Restore/VPhoneRestoreCommand.swift`.

- [ ] **Step 1: Cherry-pick** `4a672e5d6b`; expect conflicts in the installer and restore registration.
- [ ] **Step 2: Resolve** by keeping the 2.9.5 source's `runKernelUpdate` body/patch pipeline and applying the boot-state, rollback and receipt changes around it. Register the `boot-commit` and `boot-rollback` commands in the 2.9.5 command list.
- [ ] **Step 3: Build** the `VPhone` scheme; expect `BUILD SUCCEEDED` and `Bundle admission passed`.
- [ ] **Step 4: Test** `FirmwareBootAdmissionTests`; expect 14/14 pass.
- [ ] **Step 5: Commit** the port.

## Task 2: Validate the commit path live

- [ ] **Step 1: Install** the ported bundle, bind `vphone26s`, stop it.
- [ ] **Step 2: Differ the selection** with a non-boot-essential kernel block; back up `PatchSelection.plist`.
- [ ] **Step 3: Update** with the helper; expect pending `B` and `installed = true`.
- [ ] **Step 4: Boot** `vphone26s --headless --wait`; expect vphoned and no panic.
- [ ] **Step 5: Stop and commit**; expect active `B`, `A` standby, `BootReceipt` `booted`.
- [ ] **Step 6: Second slot:** restore the selection, update, boot, commit; expect active `A`, `B` standby and a second booted receipt.
- [ ] **Step 7: Restore** the twin's original selection and report the receipts.
