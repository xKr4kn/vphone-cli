# Upstream 2.17.1 Port and VM Infrastructure Validation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox syntax.

**Goal:** Forward-port the local sysent[536] tracer, A/B kernel admission, and Launchpad boot-commit/boot-rollback verbs onto upstream 2.17.1, then validate the complete host + bundle + guest infrastructure on `vphone26`.

**Architecture:** Branch `port/upstream-2.17.1` from `upstream/main` (`7a8d6c39`, 2.17.1). Reuse the 2.15.2 A/B implementation from `230b65a9`/`c5b244aa`/`ee47b4f0`; reuse the Launchpad verbs from `0cb118a6`; reuse the sysent patch from `9a22d405`. The app remains 2.17.1, helper bumps to 22, bundle stays 2.17.1, minimum bundle components become 2.17.1. The installed 2.17.1 app and helper are exercised from the worktree, then `vphone26` is bound to the new bundle for A/B and guest smoke tests.

**Tech Stack:** Swift 6, Xcode workspace, Virtualization.framework, vphone-launchpad-cli, vphoned RPC, XNU patch pipeline.

## Global Constraints

- Do not rebase or push local `main`; it is historical and 845 commits behind upstream.
- Keep the vendor remote read-only with `upstream`; push only to `origin` (`xKr4kn/vphone-cli`).
- `MARKETING_VERSION = 2.17.1`; `CURRENT_PROJECT_VERSION = 22` because the helper protocol changes.
- `VPhoneLaunchpadBundleStore.minimumBundleComponents = (2, 17, 1)` for the new contract.
- No Python, no Homebrew runtime dependency, no hardcoded patch instruction words.
- The existing `vphone26` machine and its restore tree are preserved; never recreate it.
